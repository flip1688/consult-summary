### รีวิว PRD / Use Case Diagram (Wallet)
- ที่ปรึกษาโชว์ตัวอย่าง Use Case Diagram แบบเน้น High Level ก่อนลง Detail เพื่อให้คน Non-technical เห็นภาพรวม โดยใช้ UML เท่าที่จำเป็น (ลดความซับซ้อนให้ทีมเข้าใจง่าย)
- คุณอายเสนอเวอร์ชันของตัวเอง: ใช้ Actor ฝั่งเดียวกัน มี Admin, Agent, Assistant (ผู้ช่วย) — Assistant ดู/add/edit group ได้, Agent add ได้เหมือน Assistant, Admin จัดการหมวดหมู่/กลุ่มเกมได้มากกว่า
- ข้อเสนอปรับปรุงจากที่ปรึกษา:
  - แก้คำผิด "VIEW" ที่สลับตัวอักษร (แนะนำเครื่องมือช่วยตรวจไวยากรณ์ในเบราว์เซอร์ เช่น Grammarly; ให้ลองเช็คว่า Draw.io มี extension ช่วยหรือไม่)
  - ระวังการใช้คำ "Actor" ซ้ำซ้อน (ทั้งตัวคนและกล่อง) ให้แยกให้ชัด
  - ควรเพิ่มบริบทว่ามีเพียง Admin เท่านั้นที่ Create Row (User Row / สิทธิ์ผู้ใช้) ได้

### แนวคิด Permission แบบ Row-based
- ที่ปรึกษาถามเชิงเทคนิคว่า Admin/Agent/Assistant จะถูกนำไปออกแบบเป็น Permission ใน Database อย่างไร
- สรุปความเข้าใจ: ควรเป็น "Database Row" (ไม่ใช่ Database User) — สร้างตาราง User Row / GateRow ที่มี toggle เปิด-ปิดสิทธิ์ แล้ว assign row เข้ากับ user แต่ละคน ผูกกับ UI อัตโนมัติ
- ถ้า Application ทำละเอียดถึงระดับนี้ ควรใส่รายละเอียดใน Excel/เอกสาร; ถ้าไม่ ก็ใส่แค่ระดับ role ในการเข้าถึงก็พอเพื่อความง่าย

### การเชื่อมโยงเอกสารและ Test Case
- ปัจจุบันมี Use Case แล้ว แต่ยังขาด Test Case (ที่มี Acceptance/Need Criteria) ซึ่งควรผูกกับ UI — บาง Use Case มีหลาย Test Case
- ที่ปรึกษาทดลองทำ link ในเอกสาร (Draw.io + PRD) โดยใช้ highlight + insert link + anchor (#) / heading / bookmark แต่พบว่าการลิงก์ข้ามแท็บ (cross-tab) ยังทำได้ไม่สมบูรณ์ — ที่ปรึกษาจะไปเช็ค/ทดลองเพิ่มเติม
- เสนอให้เพิ่ม Column ใน Test Case เพื่อเชื่อม Use Case → Feature → UI → Test → Code number (เช่น TC001, hashtag ใน ClickUp/Code) แบบ mind map เพื่อให้ Dev team กับ Business team คุยกันตรงกัน
- เครื่องมือ: ทีมใช้ ClickUp เป็นหลัก (Gantt chart ใน ClickUp). พูดถึง Confluence + Jira (Atlassian) ที่ integrate กับ software development ได้ดีกว่า แต่ต้อง research เรื่องค่าใช้จ่าย. ClickUp มี Template ใส่ Test Case ได้ (บาง template อาจต้องเสียเงิน). GitHub ก็ลิงก์ issue/code ได้. ที่ปรึกษาของโปรเจกต์ตัวเองใช้ Google Sheet วางเอง

### Markdown + Mermaid + Sequence Diagram
- ที่ปรึกษาโชว์ตัวอย่างเอกสารทำเป็น Markdown (ยังไม่สมบูรณ์) รวมถึง Sequence Diagram ที่แสดง flow: user → UI (member service) → link database → audit lock
- เหตุผลที่ควรมี Sequence Diagram: ให้ทีม dev เข้าใจ flow การทำงานก่อนเขียนโค้ด และช่วย debug (เห็นว่าปัญหาน่าจะอยู่ service ไหน) โดยไม่ต้องลงลึกระดับ code
- เบื้องหลัง Markdown/Mermaid เป็นแค่ text (standard) จึงให้ AI ช่วย generate/convert ได้ง่าย โดยไม่ต้องมีความรู้เทคนิคลึก
- แนะนำ workflow ใช้ AI: เปิด AI, ให้ plan ก่อน (plan mode / Copilot), ใส่ข้อมูลดิบ, สั่งแปลงเป็น Markdown, แล้ว review; ถ้า token เยอะให้ผ่าน Google Translate เป็นอังกฤษก่อนเพื่อความเร็ว
- เป้าหมายปลายทาง: รวบเอกสารเป็น Markdown ที่ร้อยเรียงกัน เพื่อใช้ทำ scoping ให้ AI เข้าใจ requirement
