## เนื้อหาสำคัญ

### การตั้งค่าเครื่องมือ (VS Code + Copilot)
- ติดตั้ง extension: Markdown และ Markdown All in One
- เปิดโปรเจกต์เป็น Folder แล้วนำเอกสารที่ทำไว้ (Google Docs export เป็น PDF) มาวางในโปรเจกต์
- แนะนำให้สั่งงานแบบ Plan ก่อนเสมอ เพื่อ review แผนก่อนปล่อยให้ทำจริง ลดการทำผิดและประหยัด token

### ทำไมต้องใช้ Markdown
- Markdown เป็นฟอร์แมต Text ที่ AI อ่านเข้าใจง่ายและกิน token น้อยกว่า PDF / Google Docs
- ใช้เป็นแหล่งข้อมูลกลาง (คลังความรู้บริษัท) ให้ AI ตอบคำถามเรื่องสถานะ/เนื้อหาโปรเจกต์ได้โดยไม่ต้องเปิดอ่านเอกสารเอง
- ผูกกับ GitHub Repository ที่เก็บทั้ง source code + เอกสาร แล้วให้ AI ค้นข้อมูลข้ามทั้งหมดได้

### เทียบกับ ClickUp และ Notebook LM
- ปัจจุบันทีมเก็บเอกสารกลางไว้ที่ ClickUp (เอา PID/Use Case ไปแปะไว้ ค้นหาเอกสารได้ แต่ยังไม่แน่ใจเรื่องระบบ search/AI ในตัว)
- ที่ปรึกษาสรุป: ถ้าทีมมี Notebook LM ใช้อยู่แล้วและใช้ได้ดี Notebook LM เป็นคำตอบที่ดี (เหมาะกับ onboarding คนใหม่ ให้ถามแทนการรื้ออ่านเอกสาร/รอ senior สอน) — ไม่จำเป็นต้องทำ Markdown เอง เว้นแต่ในอนาคตอยากพัฒนาระบบของตัวเองที่ไม่พึ่ง Notebook LM
- ข้อสังเกต: Notebook LM ทำ UT case ได้แต่บางส่วนเพี้ยน และยังไม่มั่นใจว่าทำ sequence diagram ได้ ต้องลองก่อน

### สาธิตสร้างเอกสารด้วย Copilot
- ใช้ Copilot เวอร์ชันฟรี โหมด Auto (เลือกโมเดลอัตโนมัติ, ความเร็ว 1x; เสียเงินจะได้ 3x–5x และโมเดลเก่งกว่า) — งานเอกสารไม่ใช่ coding จึงพอใช้ฟรีได้
- สั่งสร้าง SRS จาก PDF requirement แล้วต่อด้วย sequence diagram (ใช้ Mermaid) — เน้นว่าต้องสั่งให้ละเอียด/specific เช่น "จาก requirement ในไฟล์นี้ ช่วยสร้าง sequence diagram ครบทุกข้อ" และ mention ไฟล์ด้วย `@ชื่อไฟล์` (เช่น `@SRS`)
- โหมดอนุมัติ: by default ถามก่อนทำ / Start Implement (ถามเป็นจุด ๆ เหมาะงานต้องตรวจ) / Start with Autopilot (ปล่อยทำจนจบ เหมาะงานง่าย)
- Markdown สร้างแล้ว view / print / export PDF ได้เลย ไม่ต้องแปลง; แก้ไขตรง ๆ ได้เหมือน Word
- ทางเลือกฟรีแบบ local: Open Code / Ollama + โมเดลฟรี เช่น Qwen (Alibaba) — ติดตั้งไม่ยากแต่กินสเปคเครื่อง ยังไม่จำเป็นตอนนี้

### Workflow BA ↔ Dev ผ่าน Repo กลาง
- โครงสร้างที่เสนอ: repo โปรเจกต์เก็บเอกสารทั้งหมด (SRS, PRD, Use Case, Test Case, Sequence) ที่ BA ทำ
- Dev สร้าง branch (แนะนำ branch/create มากกว่า fork) เริ่มทำแต่ละฟีเจอร์ เช่น F001 โดยให้ AI อ่าน Markdown requirement ทั้งหมด แล้ว push code กลับ repo เดียวกัน
- ได้ traceability: BA แก้ requirement → Dev เห็น real-time ผ่าน GitHub, review ว่าโค้ดล้อตาม requirement ไหม, ส่ง bug ให้ review ได้ ลดการอธิบายปากเปล่า/ส่งไฟล์รายคน
- ที่ปรึกษาแชร์ไฟล์ตัวอย่าง 3 ไฟล์ (Use Case diagram, SRS ที่มีลิงก์ไป Functional Requirements, Sequence diagram) เพื่อโชว์หน้าตา "link" ที่ควรเป็น

### ปัญหาเทคนิคที่เจอในเซสชัน
- ลิงก์ข้ามไฟล์ (SRS ↔ diagram) ยังกดไม่ไป เพราะต้องมีไฟล์ปลายทางครบและตั้งค่า Markdown Preview extension ให้ถูก — ยังแก้ไม่จบในที่ประชุม แต่สรุปว่าถึงลิงก์ไม่ได้ก็ยังเห็นภาพรวมได้

## การตัดสินใจ / ข้อตกลง
- เห็นพ้องเหตุผลของการ convert เอกสารเป็น Markdown เพื่อใช้เป็นแหล่งข้อมูลกลางให้ AI และเชื่อม BA ↔ Dev
- ถ้าทีมมี Notebook LM ใช้ดีอยู่แล้ว ให้ใช้ต่อได้ ยังไม่จำเป็นต้องบังคับทำ Markdown ทั้งหมด — Markdown เป็นตัวเลือกเสริม/สำหรับอนาคต
